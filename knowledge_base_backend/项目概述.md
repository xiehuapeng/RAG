# 项目概述

本文记录当前代码已经实现的后端能力和运行边界。设计中的后续改造会单独标记，不与现状混写。

## 项目定位

当前项目是一套知识库问答后端，将文档上传、结构化解析、切片入库、混合检索、模型生成、会话管理、反馈和运营统计串成完整链路，并向 Vue 前端提供统一 API。

## 技术与模型

- Web：`FastAPI + Uvicorn`
- ORM 与业务存储：`SQLAlchemy + SQLite`
- 向量存储：`Chroma`
- 文档与 RAG 编排：`LangChain`
- Embedding：`BAAI/bge-small-zh-v1.5`
- 问题理解：主备顺序可配置；当前示例和本机为远程 `deepseek-v4-flash` 优先、Ollama `gemma4:e4b` 降级，无配置时代码默认顺序相反
- 模型精排：本地 `BAAI/bge-reranker-base` Cross-Encoder，前 16 个候选有界加分
- 回答生成：`deepseek-v4-flash`，通过 OpenAI 兼容接口调用

运行时模型配置来自 `.env`、`.env.local` 或环境变量。`sys_model_config` 和前端配置页当前用于配置记录管理，不会动态覆盖已经加载的进程配置。

## 已实现能力

- 登录、登出、服务端 session token 和管理员鉴权
- 文档重名检查、单个/批量上传、结构化解析和切片
- 索引重建、重新切片、知识单元查询、编辑和删除
- 规则优先、模型按需补充的问题理解
- 追问识别、query 改写、搜索词和搜索 query 扩展
- 关键词与向量多路召回、规则粗排、可选 Cross-Encoder 精排、门槛过滤和结果分桶
- 证据上下文构建、LLM 回答生成、引用和推荐追问
- 非流式回答和 SSE 流式回答进度
- 问答会话、消息、检索日志、问题理解日志和反馈
- 文档量、切片量、检索量、反馈率、热门问题、无答案问题和趋势统计

## 数据分层

- `data/knowledge_base.db`：用户、token、文档、切片、会话、消息、日志、反馈和模型配置
- `data/chroma/`：chunk embedding 和向量索引
- `data/uploads/`：原始上传文件
- `logs/`：按运行配置生成的应用与单题问答日志

## 文档入库流程

1. 接口校验文件类型、大小、数量和重名情况。
2. 原始文件保存到 `data/uploads/`。
3. `documents_langchain.py` 调用解析器提取正文和章节结构。
4. 按配置切分 chunk，并将文档与 chunk 写入 SQLite。
5. `vector_store.py` 生成 embedding 并写入 Chroma。
6. 文档状态更新为 `ready`；异常时保留错误信息供前端查看。

后端上传白名单为 `txt/md/json/csv/docx/pdf/xls/xlsx`。

同名覆盖上传走独立保护路径：先解析新文件，拒绝空内容，准备新切片和向量，再事务替换旧记录。提交前失败会回滚并清理新资源，保留旧文档；提交后清理旧文件及向量，清理失败记日志，不撤销已成功的替换。普通索引重建和单块编辑暂不具备同等保护，SQLite 与 Chroma 也不是分布式事务。

## 当前问答流程

1. 保存用户消息，读取最近对话和会话摘要。
2. `query_understanding.py` 始终执行关键词、追问和路由规则。
3. 规则无法稳定判断或需要语义补充时，调用配置的主 provider，失败且调度预算尚有剩余时尝试备用 provider。
4. 统一产出 `QueryUnderstandingResult`，包含路由、改写 query、关键词、实体和检索扩展。
5. `route=out_of_scope` 时跳过 RAG 链路并返回范围外提示。
6. `route=kb_qa` 时，`retrieval_langchain.py` 对原问题、改写问题和扩展 query 做多路关键词/向量召回。
7. 对候选 chunk 做规则融合打分及可选模型加分，再做门槛过滤和来源分桶；桶内按最终得分优先选取，追问精排使用改写 query。
8. `qa_langchain.py` 组织历史、会话摘要和证据上下文，调用 LLM 生成回答。
9. 保存回答、引用、检索日志和更新后的会话摘要，返回完整响应或 SSE 事件。

当前 SSE 进度步骤为：

```text
start -> understanding -> retrieving -> filtering -> generating -> completed
```

## 关键代码入口

- `app/main.py`：应用创建、CORS、路由注册、启动初始化、异常封装和前端静态托管
- `app/routers/`：认证、文档、聊天、看板和配置接口
- `app/services/documents_langchain.py`：当前文档解析与入库主实现
- `app/services/query_understanding.py`：当前规则与单次模型补充的问题理解实现
- `app/services/retrieval_langchain.py`：当前多路召回、规则重排和门槛过滤实现
- `app/services/qa_langchain.py`：Prompt、证据上下文、回答和会话摘要实现
- `app/services/chat.py`：问答链路编排、日志、兜底和 SSE 输出
- `app/services/vector_store.py`：Chroma 和 embedding 封装

## API 分组

- 健康检查：`GET /health`
- 认证：`/api/auth/*`
- 文档：`/api/documents/*`
- 聊天：`/api/chat/*`
- 看板：`/api/dashboard/*`
- 配置：`/api/config/*`

接口统一使用以下业务响应结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

## 当前实现与规划边界

- 当前问题理解仍是“规则 + 一次模型调用同时完成分类和扩展”；[问题理解分层方案设计](问题理解分层方案设计.md) 描述的分类层、扩展层和并行首轮检索尚未实现。
- 已接入专用 rerank 模型，但保留规则分、来源配额和覆盖度选择；并非全量纯模型排序，尚需固定业务评测集比较质量和延迟。
- 问题理解主备共享 60 秒调度预算，单次 HTTP 超时默认 45 秒并受剩余预算限制；禁用远程 SDK/transport 隐式重试。HTTP 超时按阶段生效，不保证整个问答请求在 60 秒内结束。
- PDF 当前依赖文本提取，不具备完整 OCR 能力；扫描型 PDF 可能无法有效入库。
- SQLite 与本地 Chroma 适合单机轻量部署，不等同于生产级多实例共享存储方案。
- 回答模型失败或证据不足时会走本地兜底，兜底结果可用但不等同于模型生成质量。
