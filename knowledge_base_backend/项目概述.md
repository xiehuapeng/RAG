# 项目概述

这是一个基于 `FastAPI` 的知识库问答后端，核心目标是把“文档上传、结构化解析、切片入库、向量检索、问答生成、会话管理、反馈统计”串成一条完整链路。

## 一句话总结

用户上传文档后，后端会把原始文件保存到本地，解析出章节结构，生成 chunk，同步写入 SQLite 和 Chroma，随后在聊天接口里通过混合检索和模型生成给出回答。

## 核心能力

- 登录和会话 token 鉴权
- 文档上传、检查重名、批量上传
- 文档解析、重建索引、重切片、单个 chunk 更新与删除
- 混合检索：关键词召回 + 向量召回 + 重排 + 门槛过滤
- 问答会话管理、消息记录、回答摘要、追问建议
- 正负反馈、热门问题、无答案问题、趋势统计
- 模型配置管理

## 运行时数据分层

- `SQLite`：业务数据、文档元数据、切片内容、会话、消息、日志、反馈、模型配置
- `Chroma`：chunk 向量、embedding 检索索引
- `data/uploads/`：原始上传文件

## 主要入口

- `app/main.py`：应用入口、路由注册、启动初始化
- `app/__main__.py`：命令行启动入口

## 主要业务链路

### 文档链路

1. 管理员上传文件
2. 后端校验类型和大小
3. 原始文件落盘
4. 解析出章节结构
5. 生成 chunk
6. 写入 SQLite
7. 同步 Chroma
8. 标记文档为 `ready`

### 问答链路

1. 用户发送问题
2. 服务端保存消息
3. 从知识库检索相关 chunk
4. 组织证据上下文
5. 调用模型生成回答
6. 保存助手回复和会话摘要
7. 返回完整回答或 SSE 流

### 运营链路

1. 统计文档、检索、反馈和趋势
2. 汇总热门问题和无答案问题
3. 提供最近反馈明细
4. 维护模型配置

## 关键说明

- 当前主问答链路已经不是“语义理解 LLM 改写 query”的旧模式
- 当前实现使用原始问题直接做检索
- `app/services/documents_langchain.py` 是文档入库主实现
- `app/services/retrieval_langchain.py` 是当前聊天主检索实现
- `app/services/qa_langchain.py` 是当前聊天主 Prompt / 生成实现

## 默认配置

- 默认管理员用户名：`admin`
- 默认管理员密码：`admin123`
- 默认会话有效期：`7` 天
- 默认检索返回数：由配置项控制
- 默认上传上限：`200MB`

## 接口分组

- 认证：`/api/auth/*`
- 文档：`/api/documents/*`
- 聊天：`/api/chat/*`
- 看板：`/api/dashboard/*`
- 配置：`/api/config/*`

## 风险和限制

- 没有完整的 PDF/OCR 解析
- SQLite 适合轻量部署
- 本地 embedding 模型和 Chroma 依赖本地环境可用
- 问答质量高度依赖文档结构、切片质量和检索结果
