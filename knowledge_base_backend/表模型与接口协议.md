# Backend 表模型与前后端接口协议

本文基于当前 `knowledge_base_backend/app/models.py`、`app/routers/*.py`、`app/schemas.py`、`app/services/*.py` 以及前端 `knowledge_base_frontend/src/api/service.js` 的实际实现整理，目标是给前后端联调、管理后台开发、接口排障提供一份统一口径。

## 1. 公共约定

### 1.1 接口基础信息

- 后端业务接口统一挂载在 `/api/*`
- 鉴权通过请求头 `x-session-token` 传递
- 除登录外，大部分接口都要求已登录
- 管理员接口额外要求当前用户 `role=admin`

### 1.2 通用响应结构

除流式接口外，后端统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

说明：

- `code=0` 表示成功
- `message` 为提示文案
- `data` 为业务数据
- 个别列表接口会附加分页字段，如 `total`、`page_num`、`page_size`

成功响应由 `app/responses.py` 中的 `success()` 生成，错误响应可能来自：

- 路由直接返回业务错误对象
- `HTTPException(detail={ code, message })`
- 鉴权依赖抛错

### 1.3 常见错误码

当前项目没有一份独立错误码枚举，存在复用和语义混用，联调时要以接口上下文为准。

| code | 含义 | 典型来源 |
| --- | --- | --- |
| 0 | 成功 | 通用成功响应 |
| 1000 | 通用业务错误 | 会话不存在、无效 feedback、模型配置不存在等 |
| 2001 | 用户名或密码错误 | 登录失败 |
| 2003 | 登录态失效 | 未传 token / token 过期 |
| 2004 | 权限不足 | 非管理员访问管理员接口 |
| 3001 | 文件格式不支持 | 文档上传校验 |
| 3002 | 文件过大 | 文档上传校验 |
| 3003 | 文档不存在 / 文档解析失败 | 文档详情、解析流程 |
| 3004 | chunk 不存在 | 文档 chunk 编辑/删除 |
| 3005 | 文件已存在 | 上传时重名且未覆盖 |
| 3006 | 源文件不存在 / 批量上传超限 | 文档存储路径回溯、批量上传校验 |

### 1.4 鉴权与权限

| 场景 | 规则 |
| --- | --- |
| 未登录接口 | 仅 `/api/auth/login` |
| 普通登录接口 | 需要 `x-session-token` |
| 管理员接口 | 需要 `x-session-token` 且 `role=admin` |

管理员接口主要包括：

- 文档上传、删除、重建索引、编辑 chunk
- Dashboard 统计接口
- 模型配置接口

### 1.5 前端调用习惯

前端当前实际调用方式如下：

- 登录态校验：`POST /api/auth/me`
- 文档列表：`POST /api/documents`
- 聊天历史列表：`POST /api/chat/sessions`
- 仪表盘接口全部走 `POST`
- 流式问答单独走 `fetch + text/event-stream`

说明：部分路由同时声明了 `GET` 和 `POST`，但前端目前主要使用 `POST`。

## 2. 数据表模型

## 2.1 表关系概览

```text
sys_user 1 --- n sys_session
sys_user 1 --- n kb_document
sys_user 1 --- n qa_session
qa_session 1 --- n qa_message
qa_session 1 --- n qa_retrieval_log
qa_session 1 --- n qa_query_understanding_log
kb_document 1 --- n kb_chunk
qa_message 1 --- n qa_feedback
```

## 2.2 `sys_user`

系统用户表。

| 字段 | 类型 | 为空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | Integer | 否 | 自增 | 主键 |
| `username` | Text | 否 | 无 | 用户名，唯一 |
| `password_hash` | Text | 否 | 无 | 密码哈希 |
| `role` | Text | 否 | `user` | 角色，当前使用 `admin/user` |
| `created_at` | DateTime | 否 | `utcnow()` | 创建时间 |
| `last_login` | DateTime | 是 | 无 | 最后登录时间 |

补充：

- 系统启动时会自动补一个默认管理员：`admin / admin123`

## 2.3 `sys_session`

登录会话表。

| 字段 | 类型 | 为空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | Integer | 否 | 自增 | 主键 |
| `user_id` | FK -> `sys_user.id` | 否 | 无 | 用户 ID |
| `token` | Text | 否 | 无 | 会话 token，唯一 |

## 2.4 `kb_document`

知识库文档主表。

| 字段 | 类型 | 为空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | Integer | 否 | 自增 | 主键 |
| `title` | Text | 否 | 无 | 文档标题 |
| `file_name` | Text | 否 | 无 | 原始文件名 |
| `storage_path` | Text | 否 | 无 | 文件落盘路径 |
| `file_type` | Text | 否 | 无 | 扩展名，不含 `.` |
| `file_size` | Integer | 否 | `0` | 文件大小 |
| `status` | Text | 否 | `pending` | `pending/processing/ready/error` |
| `error_message` | Text | 是 | 无 | 解析失败原因 |
| `chunk_count` | Integer | 否 | `0` | 当前 chunk 数 |
| `created_by` | FK -> `sys_user.id` | 否 | 无 | 上传人 |

| `updated_at` | DateTime | 否 | `utcnow()` | 更新时间 |

说明：

- `storage_path` 当前保存的是实际落盘路径
- 文档上传后会立即进入解析、切块、向量写入流程

知识库切片表。

| 字段 | 类型 | 为空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |

- `(document_id, chunk_index)` 唯一

## 3. 接口协议

## 3.1 Auth

### `POST /api/auth/login`

- 鉴权：否
- 请求体：

```json
{
  "username": "admin",
  "password": "admin123"
}
```

- 成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user_id": 1,
    "username": "admin",
    "role": "admin",
    "token": "session-token"
  }
}
```

- 失败响应：

```json
{
  "code": 2001,
  "message": "username or password invalid",
  "data": null
}
```

### `POST /api/auth/logout`

- 鉴权：登录用户
- 请求头：`x-session-token`
- 请求体：无
- 成功响应：

```json
{
  "code": 0,
  "message": "logged out",
  "data": null
}
```

### `POST /api/auth/me`

- 鉴权：登录用户
- 请求头：`x-session-token`
- 请求体：无
- 成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user_id": 1,
    "username": "admin",
    "role": "admin"
  }
}
```

```json

  "page_size": 10
```

```json
{

    {

      "title": "开户手册",

      "file_size": 1024,
      "status": "ready",
      "chunk_count": 12,
      "created_at": "2026-04-17T10:00:00"

  ],
  "total": 1,
  "page_num": 1,
  "page_size": 10

```

### `POST /api/documents/upload/check`

- 鉴权：管理员
- 请求体：

```json
{
  "file_name": "开户手册.docx"
}
```

- 成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "exists": true,

      "id": 1,

      "status": "ready",
      "updated_at": "2026-04-17T10:00:00"
    }
  }

```

### `POST /api/documents/upload`

- 鉴权：管理员
- Content-Type：`multipart/form-data`
- 表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 否 | 自定义标题 |
| `file` | file | 是 | 上传文件 |
| `overwrite` | bool/string | 否 | 是否覆盖同名文件 |

- 成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "title": "开户手册",
    "status": "ready"
  }
}
```

### `POST /api/documents/upload/batch`

- 鉴权：管理员
- Content-Type：`multipart/form-data`
- 表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `files` | file[] | 是 | 多文件上传 |
| `overwrite` | bool/string | 否 | 是否覆盖 |

- 成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "file_name": "a.docx",
      "status": "ready",
      "document_id": 1,
      "message": "uploaded"
    },
    {
      "file_name": "b.pdf",
      "status": "error",
      "document_id": null,
      "message": "file already exists"
    }
  ]
}
```

#### SSE 事件总览

| event | 含义 | payload 结构 |
| --- | --- | --- |
| `start` | 建立流式会话 | `message_id`, `session_id` |
| `progress` | 流程图步骤状态 | `current_step`, `message`, `steps[]` |
| `understanding` | 问题理解结果 | `route`, `confidence`, `rewrite_query` 等 |
| `status` | 当前阶段文案 | `phase`, `message` |
| `evidence` | 检索与证据结果 | `query`, `analysis`, `evidence[]` |
| `delta` | 增量回答片段 | `content` |
| `end` | 结束事件 | `answer`, `summary`, `suggestions` |
| `error` | 流式错误 | `code`, `message` |

## 4. 前后端对接注意事项

### 4.1 当前前端依赖的关键约定

- 所有普通接口都要求返回 `{ code, message, data }`
- 文档列表额外依赖 `total/page_num/page_size`
- 聊天详情依赖 `summary` 和 `messages[].references`
- 非流式消息接口依赖 `suggested_questions`
- 流式问答依赖 `start/progress/understanding/status/evidence/delta/end/error` 事件名

### 4.2 已知实现特点

- 部分接口同时支持 `GET` 和 `POST`，但前端主要调用 `POST`
- `related_chunks` 与 `references` 当前重复
- `storage_path` 是真实文件路径，属于内部字段，不建议前端长期强依赖
- 错误码存在复用，后续如果要做开放接口，建议单独整理错误码表
- 管理员接口和普通接口混在同一套后端里，联调时要特别注意角色权限

### 4.3 如果后续要继续规范化

建议优先做这几件事：

1. 补一份统一错误码枚举，解决 `3003/3006` 等复用问题。
2. 给每个响应补标准 schema，而不是仅靠代码约定。
3. 把 `GET/POST` 双声明的接口收敛成单一方法。
4. 把聊天 `references`、`related_chunks`、`evidence` 的口径统一成一套字段模型。
