# 前端设计方案

## 1. 设计目标

本方案根据《数智化运营知识库_功能设计页面元素.html》整理，目标是设计一套基于 `Vue3 + JavaScript + Element Plus` 的后台前端界面，覆盖以下核心场景：

- 登录与权限进入
- 文档上传与解析结果查看
- 知识切片浏览与维护
- 智能问答与引用来源展示
- 运营看板与统计分析
- 模型配置与基础管理

整体风格要求：

- 简洁清晰
- 蓝白主调
- 信息层次明确
- 操作提示人性化
- 适合运营人员和管理人员长期使用

## 2. 视觉风格

### 2.1 主色调

- 主色：蓝色
- 辅助色：浅蓝、灰白、成功绿、警告橙、错误红
- 背景色：浅灰白
- 卡片色：纯白

推荐色值：

- `#2F6BFF`：主按钮、链接、选中状态
- `#5B8FF9`：辅助强调
- `#EAF2FF`：浅蓝背景
- `#F5F7FA`：页面背景
- `#1F2D3D`：标题文字
- `#606266`：正文文字

### 2.2 视觉原则

- 页面留白充分，避免信息堆叠
- 卡片化布局，降低阅读压力
- 操作按钮集中在区域右上角或底部
- 状态信息使用标签和颜色区分
- 长文本区域支持折叠、展开和复制

### 2.3 交互风格

- 默认操作都有明确提示
- 危险操作二次确认
- 上传、解析、重建索引等耗时操作显示进度
- 空状态要有引导文案，不显示冷冰冰的空白页
- 错误提示要明确原因和处理建议

## 3. 技术方案

### 3.1 技术栈

- 框架：Vue 3
- 语言：JavaScript
- UI 库：Element Plus
- 路由：Vue Router
- 状态管理：Pinia
- 请求库：Axios
- 图表：ECharts

### 3.2 工程建议

建议采用如下结构：

```text
src/
├─ assets/
├─ components/
├─ layouts/
├─ pages/
├─ router/
├─ store/
├─ api/
├─ utils/
└─ App.vue
```

如果项目后续需要扩展为正式后台，建议增加：

- 权限路由守卫
- 登录态持久化
- 统一请求拦截器
- 统一错误处理
- 组件级加载态和空状态封装

## 4. 页面结构

根据页面元素，建议将前端拆分为以下几个主页面：

1. 登录页
2. 首页 / 总览页
3. 文档管理页
4. 文档详情 / 解析结果页
5. 智能问答页
6. 运营看板页
7. 模型配置页

## 5. 页面设计

## 5.1 登录页

### 目标

提供简洁、明确、低干扰的登录入口，强调管理员身份进入。

### 布局

- 左侧：品牌区，展示系统名称、简介、蓝白渐变背景
- 右侧：登录卡片，包含账号密码输入、记住我、登录按钮

### Element Plus 组件

- `el-card`
- `el-form`
- `el-form-item`
- `el-input`
- `el-checkbox`
- `el-button`
- `el-alert`

### 交互

- 输入框支持回车登录
- 登录失败提示精确到“账号或密码错误”
- 如果无权限，提示“当前账号无访问权限”
- 登录按钮在请求中显示 loading

### 提示文案

- 用户名输入框：请输入用户名
- 密码输入框：请输入密码
- 登录按钮：登录系统
- 辅助提示：仅运营管理员可登录

## 5.2 首页 / 总览页

### 目标

作为登录后的入口页，用于快速查看系统状态和常用入口。

### 布局

- 顶部：页面标题、当前用户信息、退出登录
- 中部：四个统计卡片
- 下部：快捷入口和最近动态

### 统计卡片建议

- 文档总数
- 切片总数
- 问答总数
- 反馈率 / 有效率

### Element Plus 组件

- `el-row`
- `el-col`
- `el-card`
- `el-tag`
- `el-empty`
- `el-button`

### 交互

- 快捷入口跳转到文档管理、问答、看板、配置页面
- 统计卡片支持点击查看明细

## 5.3 文档管理页

### 目标

提供文档上传、筛选、列表查看、删除等管理能力。

### 布局

- 顶部：筛选区
- 中部：文档列表表格
- 右侧或顶部：上传入口
- 底部：分页器

### 筛选项

- 关键字搜索
- 文档状态筛选
- 类型筛选
- 时间范围筛选

### 列表字段

- 文档标题
- 文件名
- 文件类型
- 文件大小
- 状态
- 切片数量
- 创建时间
- 操作

### 操作按钮

- 查看详情
- 查看切片
- 删除
- 重新解析

### Element Plus 组件

- `el-form`
- `el-input`
- `el-select`
- `el-date-picker`
- `el-table`
- `el-table-column`
- `el-pagination`
- `el-dialog`
- `el-upload`
- `el-button`
- `el-popconfirm`

### 交互

- 上传后自动显示解析进度
- 上传失败时说明原因，不只给“失败”两个字
- 删除前弹出确认框
- 状态使用颜色标签区分：
  - `pending`：待处理
  - `processing`：处理中
  - `ready`：可检索
  - `error`：失败

### 人性化提示

- “支持拖拽上传，也可以点击选择文件”
- “单次上传完成后会自动进入解析流程”
- “解析完成后，文档会自动参与知识库检索”

## 5.4 文档详情 / 解析结果页

### 目标

用于查看单个文档的解析状态、正文切片、元数据和检索准备情况。

### 布局

- 顶部：文档基本信息卡片
- 中部：解析状态与进度信息
- 下部：切片列表或树形结构

### 信息展示

- 文档名称
- 文件类型
- 上传时间
- 当前状态
- 错误信息
- 切片总数

### 切片展示方式

建议采用两种视图：

1. 列表视图：适合快速查看每个切片
2. 树形视图：适合按章节展开浏览

### 切片列表字段

- 切片编号
- 切片摘要
- 关键词标签
- 来源章节
- 向量主键

### Element Plus 组件

- `el-descriptions`
- `el-timeline`
- `el-tree`
- `el-table`
- `el-collapse`
- `el-tag`
- `el-tooltip`
- `el-button`

### 交互

- 点击切片可展开完整内容
- 支持一键复制切片内容
- 支持重新切分和重建索引
- 支持查看该文档被检索命中的历史日志

## 5.5 智能问答页

### 目标

提供面向运营人员的问答窗口，支持历史会话、快捷提问、引用来源、反馈等能力。

### 布局

- 左侧：会话列表
- 中间：对话区域
- 右侧：引用来源、推荐问题、命中片段

如果屏幕较窄，右侧可折叠为抽屉。

### 对话区设计

- 用户消息左对齐或右对齐统一风格
- AI 回复独立卡片样式
- 引用信息放在回复下方折叠区域

### 功能点

- 新建会话
- 切换会话
- 发送问题
- 查看回答引用
- 反馈“有用 / 无用”
- 一键复制回答

### Element Plus 组件

- `el-aside`
- `el-main`
- `el-scrollbar`
- `el-input`
- `el-button`
- `el-avatar`
- `el-card`
- `el-collapse`
- `el-drawer`
- `el-tag`
- `el-rate` 或自定义反馈按钮

### 交互

- 回车发送，`Shift + Enter` 换行
- 发送后按钮变为 loading
- 回答生成中显示“正在检索相关知识，请稍候”
- 引用来源支持点击跳转到文档详情

### 人性化提示

- “你可以直接输入业务问题，也可以从推荐问题中点选”
- “当前回答基于知识库检索结果生成”
- “如果命中不足，建议补充更具体的场景或对象”

## 5.6 运营看板页

### 目标

面向管理人员展示系统使用情况、问答效果和文档质量。

### 布局

- 顶部：核心指标卡
- 中部：趋势图和排名图
- 底部：明细表格

### 建议指标

- 提问总量
- 文档总量
- 切片总量
- 有效回答率
- 无答案问题数量
- 用户反馈满意率

### 图表建议

- 折线图：提问趋势
- 柱状图：高频问题 Top N
- 环图：反馈分布
- 表格：无答案问题列表

### Element Plus 组件

- `el-card`
- `el-table`
- `el-progress`
- `el-tag`
- `el-row`
- `el-col`

### 交互

- 支持时间范围筛选
- 支持按模块筛选
- 支持导出统计结果

## 5.7 模型配置页

### 目标

管理检索和回答相关的模型配置，方便后续扩展。

### 布局

- 顶部：模型列表
- 中部：模型配置表单
- 右侧：当前启用状态和说明

### 字段建议

- 模型类型
- 模型名称
- 配置内容
- 是否启用
- 更新时间

### Element Plus 组件

- `el-table`
- `el-form`
- `el-input`
- `el-switch`
- `el-select`
- `el-dialog`

### 交互

- 新增模型时弹窗表单
- 编辑模型时预填当前值
- 切换启用状态时显示确认提示

## 6. 混合检索页元素映射

从页面元素角度，混合检索结果建议这样展示：

### 6.1 搜索结果卡片

每条结果建议包含：

- 标题
- 所属文档
- 切片编号
- 关键词命中标签
- 向量相似度
- 综合得分
- 是否双通道命中

### 6.2 结果排序提示

在结果列表上方提示：

- 已按“关键词命中 + 语义相似 + 标题命中 + 新版本优先”排序

### 6.3 高亮规则

- 关键词命中内容高亮
- 标题命中时在标题后标记“标题命中”
- 同时命中两个通道的结果显示“双通道命中”标签

## 7. 组件拆分建议

建议拆成以下基础组件：

- `AppLayout`：整体布局框架
- `SidebarMenu`：左侧导航
- `PageHeader`：页面标题和操作区
- `StatCard`：统计卡片
- `StatusTag`：状态标签
- `UploadPanel`：上传面板
- `ChunkList`：切片列表
- `ChatWindow`：问答窗口
- `ReferencePanel`：引用来源面板
- `EmptyState`：空状态组件
- `ConfirmAction`：危险操作确认封装

## 8. 页面交互规范

### 8.1 操作反馈

- 所有提交类操作都应有 loading 状态
- 成功时使用轻量 toast 提示
- 失败时返回明确错误原因

### 8.2 空状态

空状态不要只显示“暂无数据”，建议带引导文案：

- “当前还没有上传文档，先上传一个文件开始构建知识库。”
- “还没有会话，点击新建会话开始提问。”
- “当前没有统计数据，系统运行一段时间后会自动生成。”

### 8.3 危险操作

包括：

- 删除文档
- 重建索引
- 清空会话

这些操作都要二次确认。

## 9. 路由建议

建议路由如下：

- `/login`
- `/home`
- `/documents`
- `/documents/:id`
- `/chat`
- `/dashboard`
- `/config`

如果后续拆成主后台和子模块，可以继续加：

- `/documents/:id/chunks`
- `/chat/:sessionId`
- `/dashboard/detail`

## 10. API 对接建议

前端建议统一封装以下接口层：

- `login`
- `logout`
- `getCurrentUser`
- `listDocuments`
- `uploadDocument`
- `getDocumentDetail`
- `deleteDocument`
- `getDocumentChunks`
- `listChatSessions`
- `createChatSession`
- `sendChatMessage`
- `getDashboardStats`
- `getModelConfigs`

请求头统一带：

- `x-session-token`

## 11. 移动端适配

虽然后台主要面向 PC，但建议兼顾窄屏场景：

- 左侧导航可收起
- 问答页右侧引用面板可抽屉化
- 表格列在窄屏时可折叠或转卡片显示
- 重要操作按钮保持可点击区域足够大

## 12. 开发优先级建议

建议先实现以下顺序：

1. 登录页
2. 主布局和侧边栏
3. 文档管理页
4. 文档详情页
5. 问答页
6. 运营看板页
7. 模型配置页

原因：

- 登录和布局是整个后台的基础
- 文档管理和问答是核心业务
- 看板和配置属于增强能力

## 13. 结论

这套 UI 方案的核心目标是：

- 让知识库管理更直观
- 让检索结果更可解释
- 让操作过程更友好
- 让蓝白风格保持清爽、专业、稳定

如果后续要直接进入实现阶段，建议以这个方案为基线，使用 `Vue3 + JavaScript + Element Plus + Pinia + Vue Router + Axios` 开发。
